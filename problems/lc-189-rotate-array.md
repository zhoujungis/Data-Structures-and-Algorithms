# 【LC 189】轮转数组：三次翻转 —— 反转是自己的逆运算

**来源**: https://zhoujungis.github.io/article/lc-189-rotate-array/
**标签**: 算法、双指针、LeetCode、面试

## 题目

给定一个整数数组 `nums`，将数组中的元素向右轮转 `k` 个位置，其中 `k` 是非负数。

示例：`[1,2,3,4,5,6,7]`, `k=3` → `[5,6,7,1,2,3,4]`。

进阶：尽可能想出**更多的解决方案**，至少有三种；空间复杂度 **O(1)** 的算法。

## 思路

- **轮转的本质是两段交换位置**：在 `n-k` 处把数组切成两段，交换左右位置（`[1,2,3,4 | 5,6,7]` → `[5,6,7 | 1,2,3,4]`）。直接交换要 O(n) 暂存，换个视角就能 O(1)。
- **三次翻转为什么成立**：**反转是自己的逆运算**（翻两次 = 恒等）。先整体翻转 —— 两段恰好左右就位，但内部顺序全反；再让两段各自翻回内部顺序。一次反转管「位置交换」，另一次管「顺序恢复」，互不干扰。
- **先取模再动手**：`k` 完全可能大于 `n`（`k=100` 配单元素数组），`k %= n` 是第一步而不是可选优化，否则翻转区间直接越界。取模后 `k = 0` 直接返回；三次翻转法在 `k = 0` 时只是区间长度为 0 的空转，天然安全。
- **区间端点不能错**：整体 `[0, n-1]`、前 k 个 `[0, k-1]`、后 n-k 个 `[k, n-1]` —— 第二轮右端是 `k-1` 不是 `k`，错一格就差一位。
- **易错的两个语言/空间坑**：Python 一行 `nums[:] = nums[-k:] + nums[:-k]` 在 `k=0` 时 `nums[-0:]` 是**整个数组**（结果变成数组接上自己），必须先取模特判并改用 `nums[n-k:]`；即使写对，右侧拼接了新列表，仍是 O(n) 辅助空间 —— 只是「看起来原地」。

## 答案

### 解法一：三次翻转（时间 O(n) / 空间 O(1)）

适用场景：面试首选，满足进阶的 O(1) 空间要求，不涉及数论。原文此解法只给出 Java 实现。

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k %= n;                          // k 可能大于 n
        reverse(nums, 0, n - 1);         // ① 整体
        reverse(nums, 0, k - 1);         // ② 前 k
        reverse(nums, k, n - 1);         // ③ 后 n-k
    }

    private void reverse(int[] a, int i, int j) {
        while (i < j) {
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++; j--;
        }
    }
}
```

### 解法二：切片拼接 + 取模（时间 O(n) / 空间 O(n)）

适用场景：Python 最省事的一行式写法，但右侧拼接产生新列表，不满足进阶的 O(1) 空间要求；必须 `k %= n` 并用 `nums[n-k:]` 规避 `k=0` 时 `nums[-0:]` 取到整个数组的坑。

```python
def rotate(nums, k):
    n = len(nums)
    k %= n
    if k == 0:
        return
    nums[:] = nums[n - k:] + nums[:n - k]
```
